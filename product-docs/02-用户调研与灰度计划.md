# 用户调研与灰度计划

## 1. 当前证据边界

本次已有证据来自：个人简历中的教育 AI/FDE 场景、既有《笔记转面试考试 Agent PRD》、GitHub Skill 方法论和公开竞品资料。**尚未完成真实 5–8 人可用性访谈，因此不虚构问卷数量、访谈原话或满意度。**

## 2. 待验证假设

1. 教师最大的阻力不是不会出题，而是不敢直接采用 AI 题；
2. 来源依据和一键审核能降低逐题核对成本；
3. “每知识点 2 条证据”比单一总分更能支持补练；
4. 三档证据状态比“掌握/未掌握”更容易被教师接受；
5. Assessment Package JSON 对教研和平台接入有价值，但对普通学生不应暴露。

## 3. 灰度对象与任务

- 2 名教师/讲师：粘贴一段真实课程材料，审核并发布；
- 2 名教研/题库运营：检查蓝图、来源与硬门禁；
- 2 名学习者：完成试答并解释是否看懂诊断；
- 1–2 名企业培训负责人：评估治理与导出需求。

核心任务：5 分钟内完成“导入→生成→审核→试答→报告”。

## 4. 观察指标

- 首次完成率、任务耗时、卡点；
- 候选题审核通过率、人工修改率、主要退回原因；
- 来源证据点击/查看比例；
- 试答完成率；
- 用户能否正确解释三档诊断；
- 教师是否愿意把结果用于补练而非高风险决策。

## 5. 访谈提纲

1. 你通常如何把课程材料变成测验？最耗时的是哪一步？
2. 哪些条件满足时，你才敢采用 AI 生成题？
3. 审核台里哪条信息最有用、哪条是噪音？
4. 你如何理解 demonstrated / developing / evidence insufficient？
5. 报告能否直接指导下一次教学动作？
6. 哪个功能缺失会阻止你持续使用？

## 6. 通过门槛

- 6/8 用户无帮助完成主流程；
- medium 风险无人误以为可以跳过人工审核；
- 80% 用户能正确解释“证据不足”；
- 无隐私或严重内容事故；
- 主要问题均有可复现步骤。
