# 测试、上线与迭代

## 自动测试

- Node 核心逻辑 25+ 断言：充分性、题量、答案、来源、难度、审核、诊断；
- Python 原验证器：验证生成的 Assessment Package；
- 静态检查：关键文件与品牌内容存在；
- 发布前本地执行上述质量门禁，并保存可复现命令。

## 浏览器端到端场景

1. 首次打开默认材料并生成；
2. medium 风险未审核时禁止试答；
3. 审核后完成全部题目并生成报告；
4. 导出 JSON；
5. 短素材显示缺口且不生成；
6. 390px 移动视口检查布局与按钮；
7. 刷新后状态恢复；
8. 线上 URL 重复执行主链路。

## 灰度与正式上线

- 灰度：GitHub Pages Beta + 5–8 名目标用户任务测试；
- 正式：自动测试、Schema 验证和线上冒烟通过后推送 main；
- 回滚：Git revert 并推送后，GitHub Pages 回到上一稳定版本；
- 监控：静态 MVP 以 Pages 状态和人工线上冒烟为主。

## P0/P1/P2 迭代

### P0
- 收集真实可用性问题；
- 增加逐题编辑、拒绝原因和反馈入口；
- 增加文件导入但先做可解析类型白名单。

### P1
- 安全的服务端 LLM 生成；
- 题库版本、审核日志、组织角色；
- 补练与无提示迁移再测。

### P2
- LMS/问卷平台真实适配器；
- 基于足够样本的题目分析与校准难度；
- 可靠性、公平性和无障碍审计。

## 真实指标填报规则

所有审核通过率、人工修改率、区分度、可靠性、学习提升和再测变化仅使用真实数据；样本不足时显示“待校准”，不得用模型估计填充。
