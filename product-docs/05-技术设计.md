# 技术选型与技术设计

## 架构

```text
GitHub Pages 静态站点
├── index.html       页面骨架
├── styles.css       响应式视觉系统
├── core.js          可测试领域逻辑
└── app.js           状态与交互
        └── localStorage（仅本机演示数据）
```

## 选型理由

- 原生 HTML/CSS/JS：零前端框架运行时，适合当天完成与静态部署；
- CommonJS 兼容领域核心：浏览器运行，同时可由 Node 直接测试；
- Python 原仓库验证器：保证 Web 产物继续遵守 Skill Schema；
- 本地质量门禁：提交前执行 Node 核心测试和 Python Schema 验证；
- GitHub Pages：以 main/docs 分支目录公开 Beta 地址，便于灰度访问。

## 核心模块

- `analyzeSource`：章节、陈述、充分性与 SOURCE_GAP；
- `createAssessment`：知识点、蓝图、2× 证据题、质量与治理；
- `validatePackage`：ID、选项、来源、分值与蓝图覆盖；
- `approvePackage`：不可变审核与 reviewer 记录；
- `diagnose`：按知识点聚合证据，输出三档状态。

## 安全与隐私

- 用户输入通过 HTML 转义后渲染；
- 不读取、不上传浏览器外文件；
- 不内置模型密钥；
- localStorage 不用于敏感学生数据；
- 正式版需服务端身份、租户隔离、审计与保留期限。

## 后续服务化

增加服务端后，将 LLM 置于 API 后端：材料解析 → 结构化模型 → JSON Schema 校验 → 规则门禁 → 人工审核。模型输出永远不直接写入 active 题库；高风险动作必须有权限与审计。
